## Notes on corrections and refutations

1. **C10: npm dist-tags (R1b).** R1b records `latest` 2.1.281 and `stable` 2.1.273. Live npm today shows `stable: 2.1.274, latest: 2.1.282, next: 2.1.282`. Dist-tags move, so this may have been true at an earlier snapshot, but the ADR must not copy the R1b values. The load-bearing inferences are unchanged: Opus 5.5 needs ≥2.1.280 (model-config.md L64), the terminal CLI is 2.1.270, the Desktop bundles 2.1.280, and the `stable` channel (2.1.274) cannot run Opus 5.5. Forge should declare a minimum version rather than a channel.

2. **C12: sandbox scope (R6 §4).** "Claude Code's sandbox covers Bash only" is imprecise. Per sandboxing.md the OS sandbox covers **Bash, PowerShell and Monitor** commands and their children (R1c §9 states it correctly). The security-relevant part of the claim holds: MCP servers, hooks and the Read/Edit/WebFetch tools are **not** sandboxed. The sandbox settings key names in R1c's table match the docs.

3. **C17: ngspice `-n` is not a mitigation for `shell` (R4b §ngspice, tool table "Adopt (sandboxed, `-n`)").** In the ngspice source, `-n` only sets `readinit = FALSE`, so it skips spinit/`.spiceinit`. The `shell` front-end command is registered unconditionally and runs `/bin/sh -c`, and no CLI flag or build guard switches it off. An untrusted netlist containing a `.control` block with `shell …` still runs host commands under `-b -n`. Keep `-n`, because it closes the auto-sourced `.spiceinit` vector, but the ADR must rely on **OS-level confinement** for untrusted netlists: sandbox-exec, srt, a container, no network and write access limited to a scratch dir. Pre-screening netlists for `.control`/`shell` is a cheap extra layer, not a boundary.

**Near-misses the ADR should keep (confirmed, with caveats):**
- C1: some hook events do not fail open. A PreModelSwitch timeout *blocks*, and the worktree events fail on any non-zero exit.
- C9: an Opus 4.7/4.8 advisor under Opus 5.5 is dropped silently, with no error.
- C11: in `-p` runs, ask rules become denials, which fails closed and suits CI.
- C14: the DRC gate must pass `--exit-code-violations`.
- C19: the novtk 7.9.3.1.1 defect rests on a single maintainer comment.
- C21: TechDraw can export a full page as DXF headlessly (`writeDXFPage`); only PDF and SVG page export need the GUI.
- C29: ProCAD's 7.80 → 0.63 mixes clarification with a fine-tuned coder.

## Method and limits
- **Local, deterministic checks first:** `claude --version`, `claude plugin eval --help`, `npm view @anthropic-ai/claude-code dist-tags` and `time`, PyPI JSON API (`/pypi/<pkg>/json`, plus the PyPI integrity/provenance endpoint for atopile), `brew info --json=v2` (kicad, freecad, calculix, gmsh), `gh api` for release, commit, tag, file and issue lookups (KiCad source mirror at tag 10.0.6, FreeCAD at 1.1.3, build123d-mcp at v0.3.87, kicad-mcp-pro at mcp-server-v3.35.0, imr/ngspice master, atopile, spec42, SysML-v2-Release, the MCP spec repo), the anaconda.org API and the NVD CVE API.
- **Primary docs:** the Claude Code docs pages were fetched as raw markdown with `curl …/docs/en/<page>.md` (hooks, env-vars, sub-agents, plugins, plugins-reference, plugin-marketplaces, plugin-evals, workflows, goal, advisor, model-config, permissions, permission-modes, sandboxing, settings-reference, mcp, headless, security, changelog) and grepped verbatim. WebFetch's model summaries were **not** trusted. The one used wrongly said SubagentStop has no block cap, which env-vars.md L374 contradicts.
- **Papers:** read from arXiv abstract and HTML full-text pages, with the specific tables located in the text. The Fusion terms came from the Wayback snapshot that R4a cites; the OMG status came from omg.org.
- **Not done:** nothing was installed, and no `claude plugin eval` was run. KiCad, ngspice, FreeCAD and atopile binaries were not executed, so exit-code and `shell` findings come from source, not runtime. C25 (no re-approval on tool changes) is based on the absence of any such feature in the docs and changelog, not a runtime test. The kicad-mcp-pro tool count (24) and its JLCPCB network tool, and the live (non-archived) Autodesk terms page, were not checked.
- Docs are a moving target. Every citation above reflects the pages as served on 2026-09-25.
