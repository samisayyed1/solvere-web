# FAIL-0001 -- mapping-compliance passes an unknown market code (EUU)

Date: 2026-09-25

## What happened

`compliance/product-profile.toml`'s `target_markets` accepted any string. A profile with
`target_markets = ["EUU"]` (a typo of `"EU"`) ran through `mapping-compliance/scripts/verify.py`
and got a clean PASS with no standards matched for that market at all -- silently, with no
error and no measurement that could ever fail. Review #2's addendum sweep (S-series probe,
K1) reproduced this directly: a profile with an unknown market code was expected to FAIL
and instead PASSed.

## Five whys

1. Why did it happen? `verify.py`'s `applicable_standards()` runs each standard's
   `applies_if` predicates against whatever string is in `target_markets`. A market code
   that matches no standard's `value` list simply matches zero standards -- the loop has no
   branch for "this code isn't a real market at all," only "this code doesn't trigger this
   particular standard."
2. Why did nothing catch that? There was no `[[market]]` table in `standards.toml` (the
   original file had zero `[[market]]` entries) and no check compared `target_markets`
   against a known-good vocabulary before using it as a predicate input.
3. Why was there no vocabulary check? `REQUIRED_PROFILE_FIELDS` only asserted that the
   `target_markets` *key* existed, not that its *values* were valid -- the schema-shaped
   check (field present) was mistaken for a content check (field correct).
4. Why wasn't the absence of a vocabulary caught earlier? Phase 3's original build treated
   `standards.toml` purely as "which standards can this profile match," never as "what are
   the only legal values a profile field may hold" -- the file had no place to declare a
   closed vocabulary, so there was nothing to check against.
5. Why (root cause)? The check's mental model was "run predicates, count matches," not
   "validate the profile, then run predicates." A profile field that maps to zero standards
   because the value doesn't exist is indistinguishable, in that model, from a profile
   field that maps to zero standards because the market genuinely triggers nothing -- both
   produce an empty `applicable` list and a PASS.

## New mechanism

- Mechanism: `standards.toml` now has a `[[market]]` table (US, CA, EU, UK, with `GB` as an
  alias of `UK`), sourced to `docs/research/R5f-compliance-data-gaps.md`. `verify.py` adds a
  `profile.target_markets_valid` measurement that compares every code in
  `target_markets` against `market_aliases(data)` and FAILs (with the unknown code(s) and
  the valid list in the remediation) if any code isn't recognised. Missing/unknown values
  are checked as their own measurement, separate from "does this map any standard."
- File(s): `plugins/forge/skills/mapping-compliance/references/standards.toml` (`[[market]]`
  rows), `plugins/forge/skills/mapping-compliance/scripts/verify.py`
  (`market_aliases`, `profile.target_markets_valid`), `docs/research/R5f-compliance-data-gaps.md`
  (sourcing), `plugins/forge/tests/systems/test_mapping_compliance.py`
  (`test_unknown_market_code_fails_with_the_specific_check_id`,
  `test_known_market_codes_pass`).

## Proof it catches the original failure

Reproduced directly by running the ORIGINAL (Phase 3 build, commit `019aa3e` /
`7a7bfa5` -- identical for this skill, unchanged from the original build through the
review #2 addendum sweep) `mapping-compliance/scripts/verify.py` and `standards.toml`
(which had zero `[[market]]` rows and no vocabulary check at all) against a profile with
`target_markets = ["EUU"]`, then the current (fixed) version against the same profile:

- **Before the fix**: `[PASS] compliance.standards_map (compliance/product-profile.toml)`,
  exit 0, `out/verify/compliance.standards_map.json` status `"pass"` (only the
  `profile.required_fields` measurement existed at all; no market check).
- **After the fix**: `[FAIL] compliance.standards_map (compliance/product-profile.toml)`,
  exit 1, `out/verify/compliance.standards_map.json` status `"fail"` --
  `profile.target_markets_valid` = `"EUU"` vs `{"equals": ""}`, `pass: false`, remediation
  `"target_markets has unknown code(s) ['EUU']; valid codes are ['CA', 'EU', 'UK', 'US'] ..."`.
- Regression test: `plugins/forge/tests/systems/test_mapping_compliance.py::test_unknown_market_code_fails_with_the_specific_check_id`
  (FAIL case, asserts the specific `profile.target_markets_valid` measurement) and
  `::test_known_market_codes_pass` (PASS case, US/EU/CA).

## Eval case

`plugins/forge/evals/review/compliance-cant-fail` (defect `CD1`): a seeded `EUU` market
code in the fixture profile, graded both on the review agent's findings and directly on
`out/verify/compliance.standards_map.json` actually showing
`profile.target_markets_valid` FAIL (`compliance-check-genuinely-fails` grader).
