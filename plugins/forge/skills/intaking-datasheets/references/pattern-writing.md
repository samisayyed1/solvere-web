# Writing extraction patterns

- **One capture group, the number.** `pattern` is a Python regex (`re.search`, case-sensitive by default); its first capture group `(...)` must match only the numeric value, not the unit. Put the unit in the surrounding (non-captured) text so the pattern also confirms the unit appears where expected: `r'Capacity:\s*([\d.]+)\s*mAh'`, not `r'Capacity:\s*(.+)'`.
- **`pdftotext -layout` reformats tables as whitespace-aligned columns**, not as prose -- a pattern written against a PDF's visual layout (`"Wall thickness    2.2 mm"`, no colon) looks different from a pattern written against prose ("Wall thickness: 2.2 mm"). Always test the pattern against the *actual* extracted text (`pdftotext -layout x.pdf - | grep -A2 -B2 "Wall thickness"`), not against how the PDF looks visually.
- **Decimal and thousands separators vary.** `[\d.]+` will not match `"3,400"` (thousands comma) or a European `"3,4"` (decimal comma) -- check the datasheet's convention and adjust (`[\d,]+` plus a post-processing step, or a locale-aware pattern) rather than silently mismatching.
- **A pattern that matches the wrong number is worse than one that matches nothing.** A page often repeats a value in a table AND in prose, or has a "typical" and a "maximum" column for the same quantity -- an overly loose pattern can silently grab the wrong column. Prefer a pattern anchored to a specific label close to the value, and spot-check the matched page number and value in `out/intake/<doc>.json` against the actual PDF page before trusting it.
- **Multi-line values.** `re.search` on a single page's text (not the whole document) means a value split across a line wrap needs `\s+` where a plain space would do, or the pattern needs `re.DOTALL`/explicit newline handling -- this skill's `pattern` strings are compiled with Python's default flags, so add inline flags (`(?s)`, `(?i)`) inside the pattern string itself if needed, e.g. `r'(?i)capacity:\s*([\d.]+)\s*mah'`.
- **A pattern matching on page 1 when the real spec is on page 4** (e.g. a table of contents or a "typical applications" blurb mentioning the same word) -- `extract()` takes the *first* page match in document order and stops, so put datasheets with a misleading early mention through a narrower pattern, or split `text_file` to exclude the front matter.
